# Summary identity diagnostic

Scope: source-only mapping of factual-summary identity acceptance and existing image identity helpers. No provider, database, or production read was performed.

## Observed factual-summary gate

The factual summary contract accepts a source package only when the package's normalized `machine` equals the locked machine and `useful_factual_candidates` finds at least one traceable candidate whose excerpt passes `candidate_mentions_machine` ([factual_machine_research.py:104](../../backend/factual_machine_research.py#L104), [factual_machine_research.py:142](../../backend/factual_machine_research.py#L142)). Traceability independently requires excerpt ID, text, source URL, locator, and an approved capture method; Grokipedia is excluded ([factual_machine_research.py:37](../../backend/factual_machine_research.py#L37)). The evidence card then copies only those accepted excerpts ([factual_machine_research.py:156](../../backend/factual_machine_research.py#L156)).

`candidate_mentions_machine` has no aliases parameter and receives a single string ([factual_machine_research.py:55](../../backend/factual_machine_research.py#L55)). A machine containing `class` enters its named-ship/class branch ([factual_machine_research.py:63](../../backend/factual_machine_research.py#L63)), so it does not use the designation-only branch. Its fallback tokenization removes generic `class`, excludes hull/pennant-shaped tokens such as `ss2` or `ss105`, and then requires the remaining distinctive tokens as one ordered phrase with only spaces/punctuation between them ([factual_machine_research.py:83](../../backend/factual_machine_research.py#L83)).

For the supplied saved display name `SS-2 through SS-8 Plunger class`, that rule leaves `through` and `plunger`, requiring the ordered phrase `through plunger`. An excerpt naming `USS Plunger` or `Plunger class` without the range wording does not match this rule. For `SS-105 through SS-162 S-class`, hyphen splitting produces `s` and `class`; `class` is generic and `s` is shorter than three characters, while `ss105`/`ss162` are discarded as hull-like tokens. The remaining required token is `through`. These are direct consequences of the present matcher; they explain the reported `no traceable exact-machine excerpts` rejection emitted by the package contract ([factual_machine_research.py:145](../../backend/factual_machine_research.py#L145)).

The current tests deliberately protect strict individual-ship and aircraft-variant behavior: they accept `HMS Queen Elizabeth` but reject Queen Mary, reject nearby B-series/designation variants, and require exact fetched excerpts ([test_factual_machine_research.py:62](../../backend/tests/functional/test_factual_machine_research.py#L62), [test_factual_machine_research.py:94](../../backend/tests/functional/test_factual_machine_research.py#L94), [test_factual_machine_research.py:244](../../backend/tests/functional/test_factual_machine_research.py#L244)). There is no direct test for a ranged class display name or for an alias accepted as a factual-summary excerpt identity.

## Existing image-identity helpers and boundary

The image path already retains structured aliases separately from the display name. `_unit_roster_aliases` preserves member units, bare name, bare designation, and comma/slash parts without changing the cache/display key ([pipeline_executor.py:7524](../../backend/pipeline_executor.py#L7524), [pipeline_executor.py:7580](../../backend/pipeline_executor.py#L7580)). `_machine_documentary_hold_roster_entries` supplies that alias list and role/year/status/built-count facts to image consumers ([pipeline_executor.py:7853](../../backend/pipeline_executor.py#L7853), [pipeline_executor.py:7883](../../backend/pipeline_executor.py#L7883)). `factual_scene_subjects` likewise maps each factual script position to that locked `machine` plus aliases ([factual_image_subjects.py:17](../../backend/factual_image_subjects.py#L17), [factual_image_subjects.py:71](../../backend/factual_image_subjects.py#L71)).

For image discovery, `reference_sources._entity_queries` takes aliases before the display name, removes a hull-range prefix, turns `S-class` into `S-class`, and issues up to two quoted category queries ([reference_sources.py:196](../../backend/reference_sources.py#L196)). Its test specifically asserts that `SS-105 through SS-162 S-class` with alias `S-class` produces `"S-class" submarine` and never sends `through` as a search operator ([test_reference_sources.py:128](../../backend/tests/test_reference_sources.py#L128)). The static-documentary page/file matching path also evaluates `[machine] + aliases` ([static_docu.py:1268](../../backend/static_docu.py#L1268), [static_docu.py:1492](../../backend/static_docu.py#L1492)); alias recognition is covered at [test_static_docu_reference_fail_closed.py:244](../../backend/tests/functional/test_static_docu_reference_fail_closed.py#L244).

These image helpers are not called by `candidate_mentions_machine`, `useful_factual_candidates`, or `factual_package_contract_warnings`; the factual-summary path receives only the flattened locked machine string. The observed candidate integration boundary is therefore the factual matcher/candidate filter, while the reusable structured identity material currently exists on the image-roster side.
